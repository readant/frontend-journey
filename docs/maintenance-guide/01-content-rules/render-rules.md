# 渲染铁律：VitePress/markdown-it 陷阱清单

> 长期维护 Markdown 知识库的实战沉淀：这几条是 VitePress 底层 markdown-it 解析器的已知行为，**违反它们会静默产生渲染错乱**（不报错、只在浏览器里表现为版式破碎）。写内容时逐条对照。

## 1. `::: 容器` 必须三行独立

标题、内容、`:::` 结束符各占一行：

```markdown
::: tip 一句话记住

内容……

:::
```

**两种破损变体都会导致容器永不闭合、吞并后续所有内容**（浏览器表现为色块超高、后续标题消失）：

- ❌ 单行：`::: tip 标题内容。:::`（全部挤在同一行）
- ❌ 两行：`::: warning 标题` + 下一行「内容…:::」（闭合符挤在内容行尾）

**根因**：markdown-it 的容器插件以"行"为单位匹配开启与闭合标记，单行写法使闭合标记永远无法被识别为独立的结束行。

## 2. 加粗紧邻全角括号会「闭合失败」

markdown-it 的 emphasis **侧翼规则**：`**X（Y）**`（右括号后紧跟非标点非空格字符）无法闭合，渲染出裸 `**`；连续多个还会**交叉嵌套**（`**A（a）**和**B（b）**` → `<strong>A（a）<strong>和</strong>B（b）</strong>`）。

**修复**：改用 HTML 标签，显示不变（VitePress 默认开启 raw HTML）：

```markdown
<strong>深拷贝（Deep Copy）</strong>
```

后跟句号（`**X（Y）**。`）则正常，无需处理——这解释了为什么问题往往集中在中文标题与术语拼接处。

## 3. 代码块语言标签只用纯语言

```markdown
```html
```

```css
```

不要写成完整 CSS 类名（如 `language-html`）。VitePress 会自行补全类名。

## 4. 站点链接必须带 base 前缀

- Markdown 链接 `[x](/03-js/...)`：VitePress 构建时自动加 base，无需操心
- **raw HTML `<a href>` / Vue 组件内硬编码链接**：不会自动加 base，必须用 `import.meta.env.BASE_URL` 拼接
- 站外绝对链接（`https://...`）不受影响

## 5. 速查内容统一放参考层

- 速查内容集中放 `docs/3-reference/1-handbook/`，学习层章节内不再保留速查部分
- 学习层页面用 `::: tip 速查卡片` 提示框链接到参考层对应章节（内容单一来源，不复制）

## 6. 可复用的验证方法（架构设计）

由于 markdown-it 的这些行为在构建期不报错，需要**结构化的验证流程**来兜底：

1. **脚本整文件渲染检测**：用项目自带 markdown-it 渲染目标文件，检测输出中残留的裸 `**`。关键技巧：**先把 `::: 容器` 行置空**（模拟 VitePress 的块级分割），并**剔除 `<pre>`/`<code>` 块**，避免误报
2. **构建产物验证**：`npm run build` 后 grep `docs/.vitepress/dist` 的 HTML，确认 `<strong>` 成对、容器变成预期的 `<div class="tip">`
3. **浏览器实测**：检查提示框高度紧凑（几十 px，而非 2000px+ 超高色块）、提示框后跟同级标题（内容未被吞入）

> 历史教训：用 `/^:::[\w-]+/` 正则扫描容器会因 `:::` 后无类型名而**永不匹配**，导致破损容器漏检；用 `s`（DOTALL）标志做跨行匹配则因贪婪匹配把多个容器一起吞掉。正则扫描只能作为辅助，最终以整文件渲染为准。
