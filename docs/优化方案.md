# 章节内容优化方案：从零基础到高级应用的培养标准

> **定位**：本方案是「学习层」各章节内容编写的**统一质量标准**，用于审查与优化 `docs/01-html`、`docs/02-css`、`docs/03-js` 下所有章节，确保学习路径符合「零基础 → 独立上手项目」的培养目标。
>
> 首次应用：`03-js/02-functions`（函数与闭包，2026-08 完成改造，作为全站样板）。

## 一、培养目标与总体原则

**总目标**：让一个完全零基础的学习者，沿着章节顺序学完后，能够独立读懂、编写、调试并部署一个真实前端项目。

**三条总体原则**：

1. **先跑通，再深挖**：每个知识点先给"能跑的最小例子 + 生活类比"，让学习者建立直觉；原理、规范、坑点放在"深入理解"阶段。
2. **新知识永远建立在已学内容上**：页面间、章节间显式标注前置依赖，不跳步、不留断层。
3. **每页必须闭环**：概念引入 → 符号解释 → 标准语法 → 深入理解 → 评估测验 → 阶梯练习，缺一不可。

## 二、七项评审标准（评审清单）

以下 7 项标准是审查任何一章的**必查项**，逐项对照打分（✅ 通过 / ⚠️ 部分 / ❌ 缺失）。

### 标准 1：概念引入 —— 生活化类比

- [ ] 新概念**先讲"它是什么、解决什么问题"**，再给代码
- [ ] 至少 1 个生活化场景类比（如"函数 = 自动售货机：投币（输入）→ 出货（输出）"）
- [ ] 避免在引入阶段直接堆术语；术语出现时立即用一句话解释
- [ ] 类比与代码一一对应（类比的每个部件都能在代码里找到影子）

### 标准 2：符号解释 —— 每个语法符号 3+ 示例

- [ ] 每个新语法符号（如 `function`、`()`、`{}`、`=>`、`return`、`;`）都有**单独一节**解释"这个符号干什么用"
- [ ] 每个符号至少 **3 个示例**：① 基础用法 ② 常见错误 ③ 正确写法对比
- [ ] 错误示例必须有"为什么错"的说明，不能只贴错误代码
- [ ] 符号解释放在该符号**首次出现的位置**，不提前不滞后

### 标准 3：教学逻辑 —— 递进顺序与掌握目标

- [ ] 知识点按「前置 → 进阶」严格排序，每页开头声明"需要先掌握"
- [ ] 每个学习阶段（页/节）有明确的 **掌握目标**（学完你能做什么），可自测
- [ ] 章节首页有**路线图**（阶段 → 目标 → 前置），让学习者知道自己在哪、下一步去哪
- [ ] 页面间用 `::: tip 已掌握？` 提示承接上页内容

### 标准 4：辅助理解 —— 类比与图示

- [ ] 抽象概念（闭包、作用域链、this、事件循环等）至少 **2 个不同角度的生活类比**
- [ ] 每章至少 **3-5 张直观图示**（ASCII / Mermaid / 表格示意），**必须包含内存模型图**（变量、引用、作用域的可视化）
- [ ] 图示配 2-3 句解读，说明"图里每个格子代表什么"
- [ ] 图示紧跟它解释的代码块，图文并排

### 标准 5：前置铺垫 —— 复杂概念前的系统性准备

- [ ] 引入复杂概念（闭包、原型、异步）前，用独立页面系统讲解其前置知识（作用域、词法环境、生命周期等）
- [ ] 前置知识页结尾设 **评估小测验（3-5 题）**，附答案解析
- [ ] 复杂概念页开头有"前置复习"区块，测验未过者回到对应前置页
- [ ] 前置与概念之间不夹带新语法，保持单一职责

### 标准 6：阶梯练习 —— 四层递进体系

- [ ] 每章结尾有**阶梯练习页**，四层递进：
  - 基础语法练习（**10 题**）—— 只练一个语法点，目标：会写
  - 功能实现练习（**8 题**）—— 组合 2-3 个知识点，目标：会用
  - 综合应用练习（**5 题**）—— 跨知识点的真实小功能，目标：会拆解
  - 项目实战练习（**3 题**）—— 可运行的小项目，目标：能独立交付
- [ ] 每道题包含：题目 → 思路引导（1-3 条提示，不直接给答案）→ 参考实现 → 易错点
- [ ] 难度标注（★☆☆ / ★★☆ / ★★★），供学习者按需选做

### 标准 7：速查表 —— 参考层术语速查

- [ ] 参考层手册（`3-reference/1-handbook/`）按知识点分类组织，**每个术语包含四要素**：定义 / 语法示例 / 使用场景 / 注意事项
- [ ] 学习层页面通过 `::: tip 速查卡片` 链接到参考层对应章节（不复制内容）
- [ ] 术语命名统一中文为主、英文为辅，与场景索引、星盘、思维导图用词一致
- [ ] 新术语入库时同步检查：场景索引（`2-scenarios/`）、星盘数据（`star-map-data.ts`）、思维导图（`mindmap-data.yml`）是否需要同步

## 五、评审流程建议

1. **单章评审**：对照七项清单逐条检查，输出 ✅/⚠️/❌ 与证据
2. **修复闭环**：按 ⚠️/❌ 逐条修复，修复后回填状态
3. **跨章一致性**：术语、类比、命名与思维导图 / 星盘 / 场景索引保持一致
4. **学习路线复查**：保证任何一章的前置知识都在前序章节中出现过
