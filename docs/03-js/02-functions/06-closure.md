## 概念引入

### 类比一：记忆背包

想象你小时候住的老房子。长大后你搬走了（**函数执行结束**），但你一直背着一个**背包**，里面装着老房子的钥匙和记忆（**定义时的词法环境**）。只要背包还在，你随时能回到老房子拿东西（**访问当年的变量**）。

**函数也一样**：内层函数定义时，把外层环境"装进背包"；即使外层函数已经执行完、人已搬走，内层函数还能通过背包访问外层变量。

### 类比二：忠诚的跟班

把返回的内层函数想成一个**跟班**。老板（外层函数）下班了，但跟班还记着老板家里的密码（外层变量）。只要跟班还活着，密码就一直在——老板家（作用域）虽然"关了门"，但跟班能随时进去拿东西。

```javascript
function makeCounter() {
  let count = 0; // 老板家的"密码"（外层变量）
  return function () {
    // 跟班（返回的内层函数）
    count += 1; // 跟班记得密码，能进来改 count
    return count;
  };
}

const counter = makeCounter(); // 制造一个跟班
counter(); // 1
counter(); // 2
// makeCounter 早已执行完（老板下班），但 count 还活着 —— 跟班的背包里有它
```

::: tip 一句话理解 **闭包（Closure）= 内层函数 + 它出生时的词法环境。函数还活着，它环境里的变量就跟着活着。** :::

## 深入理解一：闭包的本质（内存图 1——执行过程）

用内存图看 `makeCounter` 从定义到调用的完整过程。内存分两块：**栈（调用过程）**和**堆（对象存活区）**。

```
【第 1 步】执行 makeCounter()：
栈：┌──────────────┐
    │ makeCounter 帧 │       堆：┌─────────────────────────────┐
    │ count = 0     │            │ （普通局部变量：函数结束即销毁）│
    └──────────────┘            └─────────────────────────────┘

【第 2 步】makeCounter 返回内层函数：
栈：┌──────────────┐           堆：┌─────────────────────────────┐
    │ makeCounter 帧 │  ←GC 回收→  │ ⛔ 销毁（没有闭包的话）        │
    └──────────────┘            └─────────────────────────────┘
    返回的匿名函数（跟班）带着一个【隐藏引用】指向 makeCounter 的环境：
    堆：┌─────────────────────────────┐
        │ makeCounter 的环境记录        │
        │   count = 1                  │  ← 跟班的背包，指向这里
        │   （被匿名函数持有，不销毁）    │
        └─────────────────────────────┘

【第 3 步】counter() 每次调用：
    跟班顺着背包引用找到 count，加 1 再返回 → 1, 2, 3, ...
```

**关键结论**：`count` 不在栈上（栈帧已销毁），而在**堆上**，被返回的函数通过**隐藏引用**长期持有——所以它"死而不僵"。

## 深入理解二：为什么闭包变量不消失（内存图 2——生命周期对比）

对比两个"命运不同"的局部变量：

```
            普通局部变量                闭包捕获的变量
创建          函数执行时                 函数执行时
函数结束后    立即销毁（被 GC 回收）      不销毁（被返回函数引用着）
谁还记着它   没人                      返回的那个函数（背包）
生命周期      与函数调用同生共死          与返回函数同生共死
```

```javascript
function ordinary() {
  let tmp = "用完就扔";
  return "done";
}
ordinary(); // tmp 随调用结束被回收

function keep() {
  let secret = "被记住";
  return () => console.log(secret); // secret 被内层函数引用 → 不回收
}
const f = keep(); // keep 结束了，但 secret 还在堆上，f 随时能读
```

## 经典应用

### 应用一：计数器（面试必考）

```javascript
function createCounter() {
  let n = 0;
  return {
    inc: () => ++n,
    dec: () => --n,
    get: () => n,
  };
}
const c = createCounter();
c.inc(); // 1
c.inc(); // 2
c.dec(); // 1
c.get(); // 1
```

### 应用二：模拟私有变量（银行账户）

`balance` 对外**完全不可直接访问**，只能通过暴露的方法操作——这就是用闭包模拟"私有"：

```javascript
function createAccount(initial) {
  let balance = initial; // 私有：外部拿不到
  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    withdraw(amount) {
      balance -= amount;
      return balance;
    },
    getBalance() {
      return balance;
    },
  };
}
const account = createAccount(100);
account.deposit(50); // 150
// account.balance;      // ❌ undefined：外部访问不到内部变量
account.getBalance(); // 150
```

### 应用三：防抖（debounce，真实项目高频）

防抖：事件触发后**延迟执行**，延迟期间再次触发就**重置计时**。`timer` 必须被"记住"，这正是闭包的用武之地：

```javascript
function debounce(fn, delay = 300) {
  let timer = null; // timer 被返回的函数闭包捕获
  return function (...args) {
    clearTimeout(timer); // 重置：取消上一次的定时器
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
const onSearch = debounce((kw) => fetchData(kw), 300);
// 输入框每敲一个字就调用 onSearch —— 只有停下来 300ms 才会真正请求
```

## 深入理解三：循环陷阱（内存图 3——var vs let）

这是闭包最经典的坑。**闭包捕获的是"变量本身"而不是"当时的快照"**：

```
❌ for (var i = 0; i < 3; i++)          ✅ for (let j = 0; j < 3; j++)
   3 次迭代共享【同一个 i】               每次迭代创建【独立的 j】
   循环结束时 i = 3                     第 0 次迭代捕获 j = 0
   3 个闭包看到的都是 3                   第 1 次捕获 j = 1
   输出：3 3 3                           第 2 次捕获 j = 2
                                         输出：0 1 2

   堆：┌───────┐                       堆：┌───┐ ┌───┐ ┌───┐
       │  i = 3 │   ← 3 个闭包都指向它        │ j=0│ │j=1│ │j=2│  ← 各指各的
       └───────┘                        └───┘ └───┘ └───┘
```

```javascript
// ❌ 错误：var 共享同一个 i
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 3 3 3
}

// ✅ 正确：let 每次迭代独立捕获
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j)); // 0 1 2
}
```

::: warning 记住结论循环里要创建"各自独立"的闭包，**用 `let` 声明循环变量**，让每次迭代都拥有独立作用域。:::

## 闭包与内存

闭包会**长期持有**外层环境的引用。滥用（比如事件监听里反复创建却不解绑）会让本该回收的变量堆积在堆上——内存泄漏。用完的闭包引用记得置空：

```javascript
let counter = makeCounter();
counter(); // 使用中……
counter = null; // 置空后，闭包及其捕获的环境才能被 GC 回收
```

## 常见坑点

- 闭包捕获的是**变量本身**，不是当时的"值"——循环陷阱正源于此
- `var` 函数作用域 + 闭包 = 共享同一变量；`let` 块级作用域 + 闭包 = 各自独立
- 忘了 `let` / `const` 而直接赋值（`x = 1`）会创建全局变量，破坏作用域隔离
- 大量不必要的闭包可能造成内存泄漏，记得**解绑事件 / 置空引用**

## 小结

- 闭包 = 内层函数 + 出生时的词法环境（"记忆背包"）
- 外层函数执行完，被捕获的变量仍在**堆上**存活，直到持有它的函数被释放
- 经典应用：计数器、私有变量（银行账户）、防抖
- 循环陷阱：`var` 共享（3 3 3）vs `let` 独立（0 1 2）
- 用完置空引用，防内存泄漏

## 评估小测验（自测后再对答案）

1. 下面的代码输出什么？

```javascript
function outer() {
  let x = 1;
  return function () {
    x++;
    return x;
  };
}
const f = outer();
f();
f();
console.log(f()); // ？
```

2. 下面的代码输出什么？

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}
```

3. 用一句话解释：为什么 `makeCounter()` 返回的函数还能访问 `count`？

4. 闭包为什么可能造成内存泄漏？怎么避免？

::: details 点击查看答案

1. `4`——每次调用 `f()` 都会让被捕获的 `x` 加 1，三次后是 4。
2. `3 3 3`——`var` 无块级作用域，3 个闭包共享同一个 `i`，循环结束时 `i = 3`。
3. 返回的函数在出生时把外层环境装进了"记忆背包"（持有隐藏引用），所以即使外层函数执行完，`count` 仍在堆上存活。
4. 闭包长期持有外层环境引用，若持有者一直不被释放（如事件监听不解除、全局变量长期引用闭包），变量无法被 GC 回收。避免：用完置空引用（`f = null`）、解除事件监听。:::
