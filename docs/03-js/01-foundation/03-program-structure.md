# 程序的基本结构：语句、表达式、分号、注释

::: tip 前置要求

需要先掌握上一页 [如何运行 JavaScript](/03-js/01-foundation/02-how-to-run)
的三种运行方式。本页讲的是**代码本身的组成**——语句、表达式、分号与注释。

:::

## 它是什么

任何 JS 程序，无论多复杂，都是由**语句（Statement）**组成的；而语句往往由**表达式（Expression）**拼装而成。先分清这两个词，再看分号、注释、代码块这些"约定俗成"的写法，你就拥有了阅读任何代码的能力。

### 1. 表达式（Expression）——"会产生一个值"的片段

表达式是**能算出结果（值）的代码**。它像数学里的算式：

```javascript
1 + 2; // 值是 3
"abc".length; // 值是 3
x > 3; // 值是 true 或 false
Math.random(); // 值是 0~1 的随机数
```

### 2. 语句（Statement）——"执行一个动作"的完整命令

语句是**让程序做一件事**的完整指令，通常以分号（或换行）结束：

```javascript
let a = 1;              // 声明语句：创建变量并赋值
a = a + 1;              // 赋值语句：修改变量的值
console.log(a);         // 调用语句：调用函数
if (a > 1) { ... }      // 条件语句：根据条件分支
for (let i = 0; ...)    // 循环语句：重复执行
```

::: tip 一句话区分

**表达式产生"值"，语句执行"动作"。**
打个比方：表达式是"算出一道菜"，语句是"把菜端上桌"。语句可以包含表达式（`let a = 1 + 2;` 中的 `1 + 2`
就是表达式），但表达式本身不一定构成完整语句。

:::

## 标准语法：语句的组成元素

### 分号 `;`——语句的"句号"

分号标记一条语句的结束：

```javascript
let name = "Alice"; // 一条语句
let age = 18; // 另一条语句
console.log(name, age);
```

**自动分号插入（ASI）**：JS 允许省略分号——引擎会在换行处自动补上。但这把双刃剑经常造成"你以为换了行，其实连成了一条语句"的坑：

```javascript
// ❌ 预期是两句，实际是一句："返回 undefined"的坑
function test() {
  return;
  1 + 2;
}
test(); // undefined（return 后面被插了分号）

// ✅ 正确写法：return 和值写在同一行
function test() {
  return 1 + 2;
}
```

::: tip 约定俗成的编写习惯

**统一加分号**（本项目采用）。自动分号插入（ASI）虽然能兜底，但"显式分号"让每条语句边界一目了然，能避开 `return`
换行这类经典坑。团队协作时，是否加分号要由格式工具（Prettier）统一，不要一半加一半不加。

:::

### 注释 `//` 与 `/* */`——写给"人"看的说明

注释**不参与执行**，是写给未来的自己和其他开发者看的：

```javascript
// 单行注释：整行到行尾都是注释
const taxRate = 0.13; // 行尾注释：只注释这一行的后半段

/*
  多行注释：
  可以跨越多行，常用于解释一段逻辑
*/
const total = price * (1 + taxRate);
```

::: tip 约定俗成的编写习惯

- 注释**解释"为什么"**（业务意图、设计决策），而不是照抄"是什么"（`// 定义变量 a` 这种废话注释不要写）
- 代码本身要"自解释"（好的命名），注释是补充，不是替代
- 暂时不要的代码**删除**，不要注释掉留在原地

:::

### 代码块 `{}` 与缩进——结构化的"分组"

用花括号 `{}` 把多条语句包成一组，形成**代码块**。`if`、`for`、函数体都会用到：

```javascript
if (isLoggedIn) {
  // 代码块：里面的语句作为一个整体
  console.log("欢迎回来");
  loadUserProfile();
}
```

**缩进**（一般 2 或 4 空格）用于**视觉上标识嵌套层级**，JS 引擎不强制缩进（写成一行也能跑），但它是团队协作的基本素养：

```javascript
// ❌ 能跑，但没法读
if (a > 0) {
  if (b > 0) {
    console.log("ok");
  }
}

// ✅ 缩进清晰，一眼看懂嵌套关系
if (a > 0) {
  if (b > 0) {
    console.log("ok");
  }
}
```

::: tip 约定俗成的编写习惯

- 项目统一 **2 空格缩进**（见根目录 `.editorconfig` / `.prettierrc`）
- 建议启用编辑器的 **Format on Save**（保存时自动格式化），让工具帮你保持统一风格
- 嵌套层级尽量浅（超过 3 层就要考虑重构），否则代码会"右倾"

:::

## 深入理解：大小写敏感与关键字

JavaScript 是**大小写敏感**的语言：`Name`、`name`、`NAME` 是三个不同的标识符。

```javascript
let Name = "A";
let name = "B";
console.log(Name); // "A"
console.log(name); // "B"
```

**保留字（关键字）**不能用作变量名：`let`、`const`、`if`、`for`、`function`、`class`、`return`
等。这些词已被语言占用，当作变量名会直接报错：

```javascript
// ❌ 语法错误：let 是关键字
let let = 1;

// ✅ 可以这样命名
let count = 1;
```

::: tip 深入一步

`let`、`const`、`var`、`function` 这些**声明型关键字**用"声明语句"告诉引擎"这里创建了一个名字"。命名规则与规范的完整版在
[变量声明](/03-js/01-foundation/05-variables) 的"命名规则"一节。

:::

## 常见坑点

- **`return` 换行**：`return` 后直接换行会被 ASI 拆成两句，导致返回 `undefined`
- **半角/全角符号**：代码里的 `;` `()` 必须是**英文半角**，中文全角符号（`；` `（）`）会直接语法报错
- **大小写写错**：`Console.log` 报错（正确是 `console.log`）；浏览器报 `is not defined` 时先检查大小写
- **注释嵌套**：多行注释 `/* */` **不能嵌套**（`/* /* */ */`
  会提前结束），需要临时注释一大段代码时，优先用单行注释或编辑器快捷键

## 小结

- **表达式**产生值，**语句**执行动作；语句由表达式等元素组成
- **分号**标记语句结束；本项目统一**显式加分号**，避开 ASI 的坑
- **注释**写给看代码的人：讲"为什么"，不讲"是什么"
- **代码块 + 缩进**结构化分组，2 空格、保存时自动格式化是团队约定
- **大小写敏感**，`Name` 和 `name` 不是一回事；保留字不能当变量名
